📚 Understanding JSON Web Tokens

🔍 What is a JWT?

A JSON Web Token (JWT) is an open standard (RFC 7519) for securely transmitting information between parties as a JSON object. It is commonly used for authentication and authorization in web applications and APIs.

A JWT consists of three parts separated by dots (.):

  • Header — Contains metadata like the signing algorithm (alg) and token type (typ).
  • Payload — Contains the claims (statements about the user and additional data).
  • Signature — Used to verify the token hasn't been tampered with.

⚙️ How JWT Works

  1. Client logs in — Sends credentials to the authentication server.
  2. Server creates JWT — Signs a token with a secret key and sends it back.
  3. Client stores token — Typically in localStorage or a cookie.
  4. Client sends token — Attaches it to subsequent API requests (e.g., in the Authorization header).
  5. Server verifies — Checks the signature and claims, then grants or denies access.

🔐 Important Security Notes

⚠️ Decoding does NOT verify authenticity This tool only decodes the token. It does not validate the signature or verify that the token is trusted.
🚫 Never share sensitive JWTs publicly Tokens may contain personal data or grant access. Treat them like passwords.
🔁 The signature cannot be reversed The signature is a cryptographic hash and cannot be decoded into readable information.
🛡️ A valid-looking payload does not guarantee trust Always verify the token on your server using the correct secret or public key.
